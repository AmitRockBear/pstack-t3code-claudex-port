### Session pickup

**You own the resume point. Read the prior trail, don't redo it.**

1. Read the project checkpoint first using [Resume storage](../references/resume-storage.md). A successful read gives the note and artifacts without requiring a path from the previous session. If the pointer is missing, use this task's T3 thread activity when available, with pagination and complete tool events. Outside T3, locate the prior trail through a local transcript under Claude Code's per-project transcripts directory at `~/.pstack/claude/projects/<encoded-cwd>/*.jsonl` (where `<encoded-cwd>` is the workspace cwd with `/` → `-`. Do not glob across other directories under `~/.pstack/claude/projects/`, that crosses workspace boundaries and reads private chats from unrelated projects), or a pushed branch. An unavailable or incomplete checkpoint needs diagnosis rather than a silent fallback. For transcript fallback, read the metadata overview and last messages first, then scan back for the decision points. Parse a long transcript in a subagent and keep the reduced timeline in the main thread (the **principle-guard-the-context-window** skill).
2. Reconstruct operational state. The branch and worktree, what already landed (`git log`, `git diff` against the base), the open todos, the decisions made. Use the prior trail to recover progress. For claims about human rulings, follow [Claims about human decisions](../../why/references/epistemics.md#claims-about-human-decisions). An agent summary is not the original ruling.
3. Diff done vs pending. Compare what shipped against what was planned and name the resume point. Recover the accepted decisions, exact authorization scope, tested revisions and available evidence. Reuse applicable proof with a recorded reason under [verify-change](../../verify-change/SKILL.md); rerun changed or uncertain behavior instead of repeating completed investigations. Execution approval does not authorize merging, auto-merge or merge-queue admission. Read artifacts linked by the resume note, including requested questions or checklists.
4. Route the remaining work to the matching playbook and pick the verdict: continue the execution, ship a finished recommendation, ratify or override a prior conclusion, or postmortem a failed run. The pickup playbook ends here. The routed playbook owns the rest.
5. Assess inherited claims against the original goal using the real artifact and recorded receipts (the **principle-prove-it-works** skill). A passing prior self-report is not proof. Use verify-change on Sol 6.1/high when implemented behavior needs fresh verification; UI checks require the user's explicit request.

**Reply:** where the prior agent stopped, what you inherited vs redid (ideally nothing redone), the resume point, and the outcome.
