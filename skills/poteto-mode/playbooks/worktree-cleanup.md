### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work.

1. Snapshot and audit only the requested repositories and cleanup scope. Record `df -h /`, then run `skills/poteto-mode/scripts/worktree-audit.mjs <repo-path> <project-transcripts-path>` under the installed plugin (principle-build-the-lever). Pass scoped transcript directories explicitly. In T3, use `t3_worktree_status` for the current thread binding and `t3_worktree_list` for branch-backed candidates. Find relevant threads with `t3_thread_list`; read each with `t3_thread_read(threadId)` and cross-check its `thread.worktreePath`, `thread.branch`, and activity. Check owned child runs with `task_status`. Detached trees still require Git inventory and explicit usage evidence. Hold candidates with incomplete activity or ownership evidence. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `.worktrees/myrepo/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest chat that touched it, then suggests a bucket. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or your own session list and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. Inspect candidate worktrees and task-owned nested children through profile routing. Read only the relevant project transcripts when usage is uncertain; delegate bulk reading only when needed. Preserve pinned or ongoing chats and their sibling worktrees, processes, ports and browser state. Hold candidates whose usage cannot be established.
4. Hold `hold-untracked` and `hold-locked` trees. Inspect tracked, untracked, ignored and submodule work with `git -C <path> status --porcelain --untracked-files=all --ignore-submodules=none` and `git -C <path> diff HEAD --ignore-submodules=none --submodule=log`; inspect changed submodules with the same status command. An empty diff leaves untracked files out. A Git lock holds the tree even when it looks clean; resolve ownership before removal. A cleanup request authorizes removing clean, merged, unused worktrees within its scope. Preserve unmerged commits, requested evidence, checkpoints and uncertain files; get an explicit discard decision before losing them. Active worktrees remain held.
5. Prune the confirmed set. Use `git worktree remove <path>` on each inspected candidate. If removal refuses, inspect the remaining files and confirm their disposal before using `--force` or removing that exact directory. Preserve branch refs and other tasks' worktrees. Run `git worktree prune`, then confirm with `df -h /` and re-list.
6. Simulators and caches are separate cleanup targets. Include them only within the user's requested scope. List specific devices, runtimes or cache paths and verify they are unused before deleting them; preserve other agents' simulators and running builds. Delete transcripts or checkpoint history only when explicitly requested, after preserving material needed for resume.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
